# 账号主页设计方案 — harnessyoung.github.io

日期：2026-08-12
状态：已确认，待实施

## 设计读数

个人账号主页，面向学术同行与开发者，语言为「浅底 + 单一深绿强调」的现代简约风格，
采用原生 CSS（无框架、无动画库）。

三个尺度：
- DESIGN_VARIANCE: 6（左右分栏，非对称，但不做实验性布局）
- MOTION_INTENSITY: 3（仅功能性反馈 + 一次进场）
- VISUAL_DENSITY: 4（首屏含真实项目卡片，非一屏一焦点）

## 背景

此前四轮方案（Editorial / Serif / Tiles / Rows 极简组，以及 OpenRouter 深色科技风）
均未通过。诊断结论：问题不在配色或间距，而在右栏始终是空灰块或纯文字，
页面缺少真实视觉内容，因此无论如何调整都显得单薄。

本方案的核心决定是**把项目卡片提到首屏右栏**，使右栏成为功能区而非装饰区。

## 视觉规范

### 颜色

| 用途 | 浅色模式 | 深色模式 |
| --- | --- | --- |
| 页面底色 | `#fbfbfc` | `#141418` |
| 卡片底色 | `#ffffff` | `#1a1a20` |
| 卡片边框 | `#e4e4ea` | `#2a2a32` |
| 主文字 | `#101014` | `#f4f4f6` |
| 次要文字 | `#a4a4ae` | `#9a9aa2` |
| 强调色 | `#0F7A52` | `#3FBF88` |
| tag 底色 | `#E3F1EA` | `rgba(63,191,136,.12)` |

深色模式强调色必须提亮到 `#3FBF88`：`#0F7A52` 在深底上对比度不足，无法通过 WCAG AA。

强调色仅出现三处：小标签文字、主按钮底色、tag 浅底。其余全部黑灰。

### 圆角

统一一套系统，不混用：
- 卡片 `14px`
- 按钮 `9px`
- tag `6px`

### 字体

系统字体栈 `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif`。
不引入 Google Fonts（避免外部请求与 FOUT）。

主标题 `clamp(2.5rem, 5vw, 4rem)`，字距 `-0.03em`，最多 2 行。
不用超大字号：右栏有卡片，两侧需视觉平衡。

## 页面结构

```
顶部导航（单行，≤64px）
├─ 左：HarnessYoung
└─ 右：GitHub / Email

首屏（左右分栏）
├─ 左栏：深绿小标签 + 2行主标题 + ≤20字说明 + 2个按钮
└─ 右栏：项目卡片 ×2（最新更新的两个）

ALL PROJECTS（仅当项目数 ≥4 时渲染）
└─ 三列网格，紧凑卡片（标题 + tag + meta，无描述）

ABOUT
└─ 两段文字，max-width 65ch，左对齐

FOOTER
└─ 单行：左版权 / 右链接，1px 上边框
```

### 卡片两种密度

- **首屏卡片**：标题、一行描述、meta、tag。信息完整。
- **网格卡片**：标题、tag、meta。无描述，更紧凑。

两者布局家族不同，避免两个区域看起来重复。

### 扩展规则

- 首屏右栏最多 2 张卡（3 张需缩小卡片，牺牲可读性）
- 项目数 1-3：不渲染 ALL PROJECTS 区，不放空占位
- 项目数 ≥4：渲染 ALL PROJECTS，放第 3 个及以后的项目

### 数据维护

项目信息硬编码在 HTML 中，手动维护。

不做 GitHub API 动态拉取：静态站点无构建流程，引入 API 会带来运行时依赖与
rate limit 问题；而项目数量少、更新不频繁，手动改一行更简单可靠。

## 交互与动效

仅四处，全部有功能理由：

1. **卡片 hover** — 边框转强调色，底色微变，`180ms cubic-bezier(.16,1,.3,1)`。
   不做 `translateY`：卡片是可点击目标，位移会使光标目标移动，反而更难点。
2. **按钮 `:active`** — `scale(.98)`，`80ms`。物理按下反馈。
3. **首屏进场** — 左栏与右栏卡片依次淡入上移（`opacity 0→1`, `y 12px→0`），
   错开 `60ms`，总时长 `500ms`，一次性。建立「先读文案再看卡片」的视觉顺序。
4. **`prefers-reduced-motion`** — 以上全部降级为瞬间到位。非可选项。

### 明确不做

- 渐变背景漂移动画（纯装饰，持续占用 GPU）
- 鼠标跟随光晕（炫技，移动端无效）
- 滚动视差 / scroll-hijack（页面仅两屏，无滚动叙事需求）
- 无限循环动画：pulse / shimmer / marquee（无内容需要持续运动）
- 自定义光标（可访问性负担）
- 版本号、构建号、时间戳、地点天气条（营销页 Tell）
- 滚动提示（`Scroll ↓`）
- 章节编号眼罩（`01 / INDEX`）

### 眼罩用量约束

全页仅 **1 个**小号大写眼罩：首屏左栏的 `BIOINFORMATICS`。

`ALL PROJECTS` 与 `ABOUT` 是普通 section 标题（正常字号与字重），不使用
`text-transform: uppercase` + `letter-spacing` 的眼罩样式。这是为避免每个 section
顶上都挂一个小标签所形成的模板化节奏。

### 技术实现

原生 CSS + 一段 IntersectionObserver 实现进场。

不引入 Motion / GSAP：本页动效量不值得增加 30KB+ 依赖。

## 响应式

- 断点 `768px`
- `<768px`：分栏塌为单栏，左栏内容在上，卡片在下，`px-4`
- ALL PROJECTS 三列网格在 `<768px` 塌为单列
- 首屏使用 `min-height` 而非 `height: 100vh`，避免 iOS Safari 地址栏导致跳动

## 可访问性

- 所有文字对比度达 WCAG AA（正文 4.5:1，大字 3:1）
- 两种颜色模式均需实际打开检查
- 卡片为 `<a>` 元素，键盘可达，焦点环可见
- 导航单行，桌面端高度 ≤64px

## 已定文案

主标题：**Building agent skills and scientific tooling**
说明句：**Reproducible workflows for bioinformatics research.**（8 词，符合 ≤20 词约束）
小标签：**BIOINFORMATICS**

卡片 meta 采用「语言 · 更新时间」两项，**不显示 skill 计数**。
理由：计数需在每次新增 skill 时手动同步，是会过期的数字；语言与更新时间维护成本低。

若后续希望展示计数，应从 `registry.json` 生成而非手写。
